Create new cron endpoint following existing poll-birdeye pattern:

**Structure:**
```typescript
import { NextResponse } from 'next/server';
import { verifySignature } from '@/lib/qstash/verify';
import { checkRateLimit, RATE_LIMITS } from '@/lib/rate-limiter/distributed';
import { getTokenOverview, BIRDEYE_CHAINS, BirdeyeChain } from '@/lib/apis/birdeye';
import { getTokensForScoring, updateTokenActivity } from '@/lib/db/birdeye-queries';
import { buildPercentileLookup } from '@/lib/scoring/normalizers';
import { calculateActivityScore } from '@/lib/scoring/activity-score';
import { calculateOpportunityScore } from '@/lib/scoring/opportunity-score';
```

**GET handler logic:**
1. Verify QStash signature (skip in dev if needed)
2. Check rate limit using BIRDEYE_ACCOUNT
3. Get all tokens for scoring (getTokensForScoring with no chain filter)
4. Build percentile lookup from all tokens (using existing volume24h, liquidity)
5. For each chain sequentially:
   a. Get token addresses for this chain (top 50 by volume)
   b. For each token, call getTokenOverview to get activity metrics
   c. Calculate activity score using metrics + percentile lookup
   d. Calculate opportunity score using activity score + liquidity
   e. Update token in DB with updateTokenActivity
   f. Add 100ms delay between API calls
   g. Log progress
6. Return summary: { chains processed, tokens updated, errors }

**Rate limiting strategy:**
- Process one chain at a time
- 100ms delay between getTokenOverview calls
- Skip token on error, continue with next
- Total: ~50 tokens/chain * 11 chains * 100ms = ~55 seconds + API time

**Cron schedule:** Run every 30 minutes (matching percentile staleness guidance from research)

Export GET function.
